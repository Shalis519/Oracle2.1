# Локальная разработка на Windows (без Replit)

Эта инструкция для тех, кто хочет скачать проект с GitHub и работать с ним
на своём компьютере (Windows 10/11), например чтобы менять фронтенд
(файлы в `artifacts/web/src`).

## Что нужно установить один раз

1. **Git** — https://git-scm.com/download/win
   Ставит также "Git Bash" — терминал, в котором команды ниже точно
   работают так же, как на Replit. Рекомендуется запускать все команды
   именно в Git Bash (а не в обычном cmd.exe).
2. **Node.js версии 24** — https://nodejs.org (выберите LTS/Current,
   версия должна быть 24.x). Проверить после установки:
   ```bash
   node -v
   ```
3. **pnpm** — менеджер пакетов, которым собран проект. После установки
   Node.js выполните:
   ```bash
   corepack enable
   corepack prepare pnpm@latest --activate
   pnpm -v
   ```
4. **Редактор кода** — рекомендуется VS Code: https://code.visualstudio.com

## Шаг 1. Скачать проект

В Replit откройте панель Git и нажмите "Push to GitHub" (если ещё не
подключено — Replit попросит авторизоваться на GitHub и создать
репозиторий). Затем на своём компьютере:

```bash
git clone https://github.com/<ваш-аккаунт>/<название-репозитория>.git
cd <название-репозитория>
```

## Шаг 2. Установить зависимости

```bash
pnpm install
```

Если увидите ошибку про "Use pnpm instead" — значит команда была
запущена через `npm install` или `yarn install` по ошибке; используйте
именно `pnpm install`.

## Шаг 3. База данных

На Replit база данных PostgreSQL создаётся автоматически. Локально нужен
собственный адрес базы данных. Проще всего — бесплатный облачный
PostgreSQL, не требующий установки на компьютер:

1. Зайдите на https://neon.tech, зарегистрируйтесь и создайте новый проект.
2. Скопируйте "Connection string" (строку вида
   `postgres://user:password@host/dbname?sslmode=require`).

(Если вы предпочитаете локальную базу — подойдёт любой обычный
PostgreSQL, установленный на компьютере, например через
https://www.postgresql.org/download/windows/.)

## Шаг 4. Ключи Clerk (авторизация)

Ключи для входа/регистрации пользователей (Clerk) уже настроены в вашем
проекте на Replit. Для локальной разработки удобнее всего скопировать
эти же ключи разработки (development keys):

1. В Replit откройте панель **Secrets** (замок в боковой панели).
2. Скопируйте значения `CLERK_SECRET_KEY`, `CLERK_PUBLISHABLE_KEY` и
   `VITE_CLERK_PUBLISHABLE_KEY`.

Эти ключи в режиме разработки работают с любого адреса, включая
`localhost`, поэтому просто скопировать их достаточно — заново
регистрироваться в Clerk не нужно.

> Изменение способов входа (например включение/выключение входа через
> Google), брендинга экрана входа и т.п. по-прежнему делается только
> через панель Auth в Replit — это не хранится в коде.

## Шаг 5. Создать файл `.env`

Скопируйте `.env.example` в `.env` в корне проекта и заполните
значениями из шагов 3–4:

```bash
cp .env.example .env
```

Отредактируйте `.env` (в VS Code) так, чтобы получилось примерно:

```
DATABASE_URL=postgres://... (из Neon)
CLERK_SECRET_KEY=sk_test_...
CLERK_PUBLISHABLE_KEY=pk_test_...
VITE_CLERK_PUBLISHABLE_KEY=pk_test_...
```

Файл `.env` никогда не попадёт в GitHub (он в `.gitignore`) — это
специально, чтобы не публиковать ключи.

## Шаг 6. Подготовить базу данных и API-клиент

```bash
pnpm --filter @workspace/db run push
pnpm --filter @workspace/api-spec run codegen
```

## Шаг 7. Запустить проект

Одной командой запускаются сразу и сервер (API), и сайт (фронтенд):

```bash
pnpm run dev
```

Откройте в браузере: **http://localhost:22333**

Чтобы остановить — нажмите `Ctrl+C` в терминале.

## Где менять фронтенд

- Страницы сайта: `artifacts/web/src/pages/`
- Общие элементы (шапка, меню, макет): `artifacts/web/src/components/layout/`
- Цвета, шрифты, тема: `artifacts/web/src/index.css`
- Изменения видно сразу в браузере без перезапуска (hot reload).

Правки в папке `artifacts/api-server` — это серверная логика (расчёты,
база данных); для чисто визуальных изменений сайта её трогать не нужно.

## Проверка перед сохранением изменений

```bash
pnpm run typecheck
```

Эта команда проверяет, что нигде нет ошибок в типах TypeScript, прежде
чем отправлять изменения обратно в Git.

## Частые проблемы

| Проблема | Решение |
| --- | --- |
| `'pnpm' is not recognized` | Установите Node.js 24, затем `corepack enable` (Шаг «Что нужно установить»). |
| `Use pnpm instead` при установке | Используйте `pnpm install`, а не `npm install`/`yarn install`. |
| Сайт открылся, но данные не грузятся / ошибка авторизации | Проверьте, что все 3 ключа Clerk и `DATABASE_URL` в `.env` заполнены без пробелов и опечаток, и что вы выполнили `pnpm --filter @workspace/db run push`. |
| `pnpm run dev` работает, но `http://localhost:22333` не открывается | Проверьте в терминале, не написана ли ошибка красным цветом — обычно это неверный `.env`. |
| Хочу вернуть изменения обратно в Replit | Сделайте `git push` в свою ветку на GitHub, затем в Replit откройте панель Git и выполните "Pull". |

## Возврат изменений на Replit

```bash
git add -A
git commit -m "Описание изменений"
git push
```

Затем в Replit: панель Git → Pull.
