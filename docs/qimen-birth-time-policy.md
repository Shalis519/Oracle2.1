# Правило времени для индивидуальной карты Ци Мэнь

## Подтверждённое книгой проекта

Учебник описывает индивидуальную карту как часовой расклад на момент рождения. Для определения столпа года используется китайский солнечный календарь и граница Ли Чунь. В найденных фрагментах учебника нет прямого требования автоматически переводить гражданское время в истинное солнечное время.

## Внешняя сверка

Открытый обзор метода Ци Мэнь описывает два режима: Local Real Time, то есть истинное местное солнечное время, и Casual Time. В том же источнике подчёркивается, что для Local Real Time нужны город/координаты и часовой пояс, а метод Цзи Жунь может сочетаться с true local solar time. Это подтверждает, что истинное солнечное время является признанным методом, но не доказывает, что каждая школа обязана использовать именно его.

Источник: https://worldzenart.org/2024/04/18/master-yi-yuns-qimen-dunjia-divination/

## Решение для проекта до пользовательского подтверждения эталона

Текущая карта рождения пока использует гражданское местное время и не должна называться картой по истинному солнечному времени. Для корректной реализации true local solar time нужны: дата, часы и минуты рождения, координаты места рождения, идентификатор часового пояса и правило учёта перехода через полночь.

Рекомендуемый технический режим: хранить исходное гражданское время, вычислять true local solar time в отдельном помощнике, показывать диагностическое различие и только после сверки с контрольными картами подключать скорректированный часовой столп к публичной карте. Это не должно менять текущие часовые карты событий.

## Контроль infengi по географии

На одной и той же дате 21.08.2026 infengi показывает для Москвы (UTC+3, долгота 37.6173) раннюю Крысу 00:29–01:28, а для Урумчи (UTC+6, долгота 87.6168) — 00:09–01:08. Следовательно, infengi учитывает географическую поправку и не использует единые гражданские двухчасовки для всех долгот.

Это подтверждает необходимость передавать координаты и часовой пояс рождения. Само сравнение пока доказывает географическую/местную солнечную поправку, но ещё не отделяет среднее солнечное время от истинного солнечного времени с уравнением времени. Для этого нужен отдельный контроль на минутной границе и расчёт поправки конкретной даты.

## Реализация в Aether Oracle

Добавлен отдельный модуль `artifacts/api-server/src/lib/qimen/birthTime.ts`. По умолчанию он рассчитывает среднее местное солнечное время по гражданскому времени, часовому поясу и долготе. Режим с уравнением времени оставлен отдельной опцией и не включён для пользовательского расчёта.

Модуль подключён только к `buildBirthChart`, то есть к индивидуальной карте рождения. Для текущих часовых карт событий, Джи Фу, Трёх Генералов и Нефритовой Девы контур не изменён. При отсутствии координаты рождения карта безопасно использует прежнее гражданское время.

Проверки: TypeScript API пройден; диагностические тесты времени и профильные тесты Ци Мэнь пройдены; frontend production build собран успешно.

## Контрольное рождение: Тараз, 05.02.1980, 16:01

Для Тараза на 05.02.1980 подтверждено историческое смещение UTC+6. При долготе 71.39843 среднее местное солнечное время получается 14:46. В infengi интервалы начинаются так, что Коза занимает 14:14–16:13, а Обезьяна начинается в 16:14. Следовательно, 16:01 попадает в Козу, что подтверждает использование географической поправки и опровергает гражданский час Обезьяны.

Наш диагностический движок даёт по гражданскому времени `庚申`, а по среднему солнечному времени `己未`. Для сверки с infengi нужно использовать `己未`.

## Истинное солнечное время: четыре контрольных рождения

При включении уравнения времени получены следующие значения: Тараз 14:32 (поправка уравнения −14.19 мин), Северобайкальск 14:54 (−2.54 мин), Хазар 04:06 (+3.72 мин), Омск 23:18 предыдущего солнечного дня (−5.01 мин).

Уравнение времени не изменило часовую ветвь ни в одном из четырёх случаев по сравнению со средним солнечным временем. Тараз остаётся Козой `己未`; Северобайкальск остаётся Козой `乙未`; Хазар остаётся Тигром `戊寅`; Омск остаётся поздней Крысой `丙子` на календарной дате 11.07.1978.

Исправление терминологии: интервал 05:27–07:26 — это час Кролика, не Тигра. Для Хазара истинное солнечное время 04:06 находится в интервале Быка по сетке infengi, а не в Кролике.

## Сопоставление с видео о солнечном и «резиновом» времени

Видео предлагает более сложную методику, чем текущая сверка с infengi. Автор использует солнечное время с поправкой долготы и уравнением времени, а также «резиновое время», где длительность дневных и ночных ветвей меняется по сезону. Отдельно вводится «совмещённое время» — пересечение солнечного и резинового интервалов.

Ключевое расхождение с текущей реализацией: фиксированные границы ранней/поздней Крысы `23:29–00:28` относятся к нашему текущему часовому движку, тогда как автор видео считает полночь серединой ветви Крысы и связывает переход даты с астрономической полуночью. Если следовать видео буквально, для рождения Анны 00:30 по Омску нужно отдельно проверить, относится ли истинное солнечное 23:18 к предыдущей календарной дате, а не автоматически сохранять дату 11 июля.

Видео также говорит не только об истинном солнечном времени, но и о сезонном «резиновом» времени. Это отдельная школа/метод активации и не может быть молча подставлена в построение карт infengi или в текущие часовые структуры. Нужен отдельный режим расчёта и контрольные примеры автора.


## Проверка калькулятора Марины, `tvoibazi.ru/hours`

Калькулятор имеет три отдельные вкладки: «Солнечное время», «Резиновое время» и «Совмещенное время», а также переключатель «Сдвоенный час Крысы». При выборе города через штатный автоподбор для Тараза установились координаты 42.9000000, 71.3666700 и UTC+6. Однако серверный результат оставил поля восхода и заката пустыми, а таблицы резинового и совмещённого времени не заполнились. Поэтому значения, полученные простой POST-отправкой без корректного cityID, нельзя считать подтверждёнными.

Нужно продолжить воспроизведение клиентского вызова после выбора города либо использовать точные функции калькулятора с правильно инициализированными полями восхода/заката. До этого этапа не подключать рассчитанные «резиновые» интервалы к карте рождения.


## Контрольные расчёты через клиентские функции Марины

После выбора координат и запуска `getTZone(); getLatitude(); getLongitude(); Vetvi(); sovmest()` в браузере получены подтверждённые значения восхода/заката и «резиновых» интервалов.

- Тараз, 05.02.1980: восход 08:26, закат 18:32; резиновый Коза 14:22–15:58, Обезьяна 15:58–17:47; гражданские 16:01 попадают в Обезьяну. В полученной клиентской таблице совмещённые интервалы для Козы и Обезьяны имели разрыв вокруг 16:01, поэтому совмещённый режим для этого момента требует отдельной проверки после штатной перезагрузки карты.
- Северобайкальск, 26.06.1986: восход 05:00, закат 22:31; резиновый Лошадь 13:13–16:30, Коза 16:30–19:33; гражданские 16:40 попадают в Козу; совмещённого интервала на 16:40 нет.
- Хазар, 17.05.1981: восход 07:12, закат 21:36; резиновый Бык 03:30–05:12, Тигр 05:12–07:14; гражданские 06:30 попадают в Тигра; совмещённого интервала на 06:30 нет.
- Омск, 11.07.1978: восход 04:41, закат 21:42; резиновый Свинья 01:47–02:44, Крыса (позд.) 02:44–06:11; гражданские 00:30 не попадают в заполненный резиновый интервал; совмещённый интервал для Петуха 23:54–00:49 не совпадает с 00:30 из-за неполного текущего клиентского состояния и требует отдельной проверки после штатного выбора Омска.

Важно: солнечная таблица на выбранном серверном результате задаёт для Тараза Козу 14:15–16:15, поэтому 16:01 в солнечном режиме — Коза. Резиновый режим для того же гражданского времени даёт Обезьяну. Это и есть смысл отдельного режима совмещения: результат зависит от пересечения двух систем, а не от одного среднего солнечного времени.
