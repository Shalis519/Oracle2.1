# Дифференциальная проверка Aether Oracle и MrJelly

Дата прогона: 21 августа 2026 года.

## Что проверено

Сравнены восемь контрольных моментов: 22.06.2026 03:00 (+08:00), 20.08.2026 12:00, ранняя Крыса 20.08.2026 00:30, поздняя Крыса 20.08.2026 23:40, а также четыре даты рождения из текущей проверки: Тараз, Северобайкальск, Хазар и Омск.

Для каждого момента сравнивались дневной и часовой столпы, номер и тип局, а также сводные значения 直符 и 直使. Часовой пояс MrJelly был приведён к часовому поясу контрольного места. Это важно: первый прогон в едином Asia/Shanghai давал ложные расхождения для Москвы, Тараза и других городов.

## Надёжные совпадения

После исправления часового пояса дневной столп совпал во всех 8 из 8 случаев, а часовой столп совпал во всех 8 из 8 случаев. В частности, для 20.08.2026 подтверждены `戊子` в раннюю Крысу и `庚子` в позднюю Крысу. Это подтверждает, что текущая передача даты и базовая шестидесятицикловая логика Aether согласуются с MrJelly на этих контрольных данных.

## Почему Ju нельзя считать прямым тестом Zhi Run

MrJelly в текущей конфигурации использует метод `时家` с выбором Yuan по земной ветви дневного столпа и фиксированной таблицей Jie Qi. В исходном коде MrJelly это видно по функции `calculateJuShu`: Yuan определяется через группы 子午卯酉, 寅申巳亥 и остальные ветви, после чего выбирается цифра из таблицы Jie Qi. В коде нет прохода по 符头, 超神 и шестиюанному расширению 芒种/大雪, которое требуется для 置闰.

Aether, напротив, в `ju.ts` явно реализует 置闰: ищет ближайший солярный якорь, вычисляет 符头, проверяет 超神, расширяет 芒种/大雪 до шести Yuan при условии `>= 9` и затем выбирает Ju по пятнадцатидневным блокам. Поэтому различия вроде 20.08.2026: Aether `阴遁一局`, MrJelly `阴遁二局` — это прежде всего различие методов, а не доказательство ошибки Aether.

## 直符 и 直使

Расхождения в 直符/直使 следуют за расхождением Ju и за различием правил раскладки. Например, для 20.08.2026 12:00 Aether даёт `天柱 / 惊门`, а MrJelly — `天任 / 生门`. Для ранней Крысы Aether даёт `天任 / 生门`, а MrJelly — `天英 / 景门`. Это нельзя использовать как основание для ручных overrides, пока не будет выбран эталон, который действительно реализует ту же 置闰-схему.

Полные промежуточные данные MrJelly сохранены в `mrjelly-2026-08-20-1200-raw.json`. Они подтверждают, что MrJelly действительно отдаёт отдельные `diPan`, `tianPan`, `jiuXing`, `baMen`, `baShen` и `anGan`, поэтому следующий этап может сравнивать расклад по девяти дворцам после выравнивания методики.

## Решение по production-коду

На этом этапе production-код Aether не изменялся. Исправление часового пояса было внесено только в дифференциальный тест. Это безопасно: тест теперь не смешивает местное гражданское время с Asia/Shanghai и не создаёт ложных обвинений в адрес часового столпа.

Следующий корректный шаг — найти или реализовать независимый эталон именно для 置闰, а затем сравнить Aether с ним по тем же контрольным датам. MrJelly полезен как проверка календаря, часового столпа, структуры промежуточных данных и общей раскладки, но в текущем режиме не является прямым эталоном Ju для проекта.
