# Открытые источники по Ци Мэнь

Дата исследования: 2026-08-19.

## Mingli

URL: https://www.mingli.info/qmdj

Открытая страница показывает калькулятор Qi Men Dun Jia с режимами Chai Bu и Zhi Run, а также переключением Hour/Day/Month/Year. Страница заявляет построение подробной карты для часа, дня, месяца и года, но формула годового Ju и исходный код построения колец публично не раскрыты.

## deminzhang/qimen-go

URL: https://github.com/deminzhang/qimen-go

MIT, Go, 25 stars, 14 forks. README заявляет turn/fei/mingfa pan, базовый Qi Men, Chai Bu и календарные зависимости. Проект полезен как независимая реализация часового расклада, но поддерживает несколько школ и не подтверждает совпадение с Mingli/Чжи Рен.

## kentang2017/kinqimen

URL: https://github.com/kentang2017/kinqimen

MIT, Python, 138 stars, 56 forks. Поддерживает 时家奇门, 拆补法 и 置闰法, а также 金函玉镜 日家奇门. Имеет готовый Python API, но это в основном часовой/дневной движок и не доказанный источник годовой карты Mingli.

## dxbuyi/qimen.skill

URL: https://github.com/dxbuyi/qimen.skill

MIT, Python, 9 stars, 4 forks. Детерминированный часовой转盘-скрипт с JSON-выводом и таблицами. Полезен для независимого сравнения входных данных и структуры результата, но README предупреждает, что упрощённое вычисление节气 может ошибаться примерно на один день.

## Taogram/taobi

URL: https://github.com/Taogram/taobi

MPL-2.0, JavaScript, 58 stars, 16 forks. Реализует последовательность: вычисление节气, получение Ju, раскладка三奇六仪, 值使/值符, 九星, 八门, 八神. Поддерживает拆补 и несколько альтернативных методов Ju. Это наиболее подходящий открытый JS-кандидат для сравнения кольцевой раскладки, но он заявляет поддержку только时家转盘奇门, а 飞盘 ещё не завершён.

## oceanjustinlin/qimen

URL: https://github.com/oceanjustinlin/qimen

MIT, TypeScript/Python web project. README заявляет детерминированный локальный часовой движок, 拆补转盘法, 甲子隐遁, 符头定位, 九星, 八门, 八神 и JSON/skill-слой. Подходит для независимой проверки архитектуры и тестового подхода, но не является источником Mingli.

## ChesterRa/mingpan

URL: https://github.com/ChesterRa/mingpan

Apache-2.0, TypeScript/MCP, 105 stars, 38 forks. README заявляет поддержку qimen_basic с 时盘/日盘/月盘/年盘, 转盘/飞盘, 拆补/茅山. Однако README не публикует подробности формулы годового Ju; исходный код нужно проверять отдельно.

## Вывод

Открытые проекты полезны для независимого сравнения календаря и часовой раскладки, но ни один найденный источник не является доказанным эталоном Mingli для годовых карт 2026/2027. Для нашего кода источник истины должен быть разделён: книга пользователя и система Чжи Рен задают правила колец, а карты Mingli 19–21 августа служат контрольными fixtures. Репозитории можно использовать для дифференциального тестирования, но не копировать их формулы без проверки против контрольных карт.

## Фактическая проверка исходников

### oceanjustinlin/qimen

`lib/qimenChart.js` показывает явную последовательность: `calculateJuByChaiBu` → `getDiPan` → `getXunHead/getFuShou/calculateFlyStep` → `getZhiFuStar` и `getZhiShiDoor` → `calculateEightDoors` → `calculateNineStars` → `calculateTianPan` → `calculateEightGods`.

`lib/QimenCalculations.js` реализует Земную тарелку как готовую таблицу `DIPAN_YANG/DIPAN_YIN`; Небесная тарелка строится вращением земной тарелки от позиции `fuShou` к позиции часового ствола по одному CLOCKWISE-маршруту для обоих направлений. Главные Врата берутся из домашнего положения `fuShou`, затем перемещаются по `flyStep`; остальные Врата раскладываются по кольцу. Это хороший прозрачный объект для дифференциального тестирования, но метод не является доказанным Mingli/Чжи Рен и прямо использует упрощённое правило для Небесной тарелки.

### ChesterRa/mingpan

`src/services/qimen/QimenService.ts` разделяет типы карт: для `年盘` используется `PanTypeCalculator.calculateYearPan`, для `月盘` — `calculateMonthPan`, для `时盘/日盘` — `JuShuCalculator` с `chaibu/maoshan`. Затем общий pipeline строит Земную тарелку, получает `refGanZhi` по типу карты, строит начальную Небесную тарелку, вычисляет旬首, и выбирает `转盘` или `飞盘`.

В `calculateXunShou` репозиторий определяет `旬首`, связанный 六仪, дворец 值符 как дворец этой 六仪 на Земной тарелке, а исходный дворец 值使 как тот же дворец. Используется центральное правило寄坤二. В README заявлены 年盘/ 月盘, но исходный код всё равно нуждается в проверке на Mingli fixtures: наличие отдельного year/month pipeline не доказывает совпадение со схемой Mingli.

### deminzhang/qimen-go

`xuan/qimen_defs.go` содержит несколько методов и типов: `QMGameYear`, `QMJuTypeSplit`, `QMJuTypeMaoShan`, `QMJuTypeZhiRun`, несколько типов盘式 и таблицу `HideJia` для旬首遁甲. Таблица `_QiMenJu` — классическая сезонная схема с Ян- и Инь-局, а не доказанная таблица годовых Ju Mingli. Репозиторий полезен для сравнения 60甲子/节气 и вариантов学校, но не как единственный источник истины.

## Промежуточный вывод

Из трёх репозиториев наиболее пригодны для раздельного сравнения: `oceanjustinlin/qimen` — как прозрачный часовой pipeline, `ChesterRa/mingpan` — как архитектурный пример раздельных часовых/месячных/годовых типов, `deminzhang/qimen-go` — как коллекция альтернативных календарных и школьных методов. Ни один из трёх не подтверждает полный алгоритм Mingli для контрольных карт пользователя без дополнительного differential testing по каждому дворцу.
