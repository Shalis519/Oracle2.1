# Архитектура рендеринга прогнозов

## Общее правило

Синтез дня и долгосрочный прогноз используют одну таблицу `forecast_text_templates`, но являются независимыми кодовыми слоями. Один рендерер не вызывает функции другого и не использует его готовый литературный текст.

Общая база является только хранилищем карточек и точкой администрирования Oracle Studio.

## Синтез дня

Синтез дня формируется через `oracle.ts` и `futuristicGenerator.ts`.

Разрешённые карточки выбираются по ежедневным категориям и контекстам, включая:

- `entity` — сущности планет и домов;
- `house` — темы домов;
- `aspect` — смысл аспекта;
- `composition` — сборка ежедневного текста.

Синтез дня не должен выбирать записи из `long_term_transit`.

## Долгосрочный прогноз

Долгосрочные транзиты формируются через `adminLongTermForecasts.ts` и `longTermTransitLiterary.ts`.

Единый ключ долгосрочной карточки имеет вид:

```text
long_term_transit / major_aspect / transitBody:aspect:natalBody
```

Примеры:

```text
sun:square:uranus
sun:opposition:mercury
pluto:trine:moon
```

Долгосрочный рендерер не должен вызывать `futuristicGenerator.ts` и не должен выбирать `composition`-карточки синтеза дня.

## Отсутствие карточки

Резервные интерпретации запрещены в обоих слоях. Если аспект найден, но карточка нужного слоя отсутствует или содержит `В разработке`, выводится техническая строка аспекта и пометка `В разработке`. Если аспектов нет, соответствующий раздел не выводится.

## Seed-данные

`runtimeSchema.ts` может создавать карточки обоих слоёв в одной базе. Это не является перекрёстным вызовом: seed только обеспечивает наличие записей. Рендерер обязан ограничивать выбор собственными категориями и контекстами.

При добавлении авторской карточки необходимо указывать её слой явно и не дублировать один и тот же текст в другом контексте без отдельного решения автора.
