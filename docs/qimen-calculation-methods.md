# Техническая документация QMDJ: методы расчёта Ji Fu

## Назначение

Этот документ фиксирует, какие методики используются в Aether Oracle для определения положения **Ji Fu / 值符** на четырёх уровнях: год, месяц, день и час. Методы на разных уровнях не являются взаимозаменяемыми. Изменение одного уровня не должно автоматически менять остальные.

Пользовательский интерфейс показывает только итоговые дату, направление, дворец и силу совпадения. Названия внутренних школ и технические обозначения предназначены для разработчиков и диагностики.

## Активная конфигурация

| Уровень | Активный метод в проекте | Основной расчётный вход | Функция |
|---|---|---|---|
| Год | Годовой слой QMDJ проекта | Солнечный год и годовой Gan-Zhi | `yearJiFuPalace()` |
| Месяц | Joey Yap Month Charts | Солнечный год, месячный Gan-Zhi и месячная структура | `monthJoeyYapJiFuPalace()` |
| День | Joey Yap Day Chart | Дневной Gan-Zhi, солнечный сезон и 甲子-якорь | `dayJiFuPalace()` + `dayJoeyYapJuForDate()` |
| Час | Zhi Run / 置闰, часовой слой | День, часовой Gan-Zhi, 旬首仪 и часовой Ju | `hourJiFuPalace()` + `buildChart()` |

**Guam Ham Hai** сохраняется как внешний контрольный режим Mingli и не является активным месячным методом Aether Oracle.

## Годовой уровень

Годовой столп определяется через `getYearInGanZhiExact()`, поэтому граница солнечного года проходит через **立春**, а не через 1 января. Для годового слоя используется отдельный 180-летний цикл с тремя 60-летними Yuan. В текущей реализации годовой слой использует Иньский Dun и последовательность Ju `[7, 1, 4]` для соответствующих Yuan.

Расчётный путь имеет вид:

```text
солнечный год → годовой Gan-Zhi → 180-летний Yuan → годовой Ju
→ годовая карта → дворец Ji Fu
```

Годовой алгоритм нельзя заменять месячным Joey Yap или дневным циклом.

## Месячный уровень: Joey Yap Month Charts

Месячный уровень рассчитывается по отдельному методу **Joey Yap Month Charts**. Месячный столп берётся из солнечного календаря через `getMonthInGanZhiExact()`. Для выбора месячной структуры используется группа земной ветви солнечного года. Активная последовательность Joey Yap в проекте — Инь 1, Инь 7 и Инь 4.

Для 2026 года годовая ветвь 午 выбирает Инь 7. Контрольная карта Mingli Joey Yap для августа 2026 подтверждает:

```text
месячный столп: 丙申
Ju: Инь 7
Ji Fu: дворец 9, Юг
```

Критически важно, что при построении месячной карты Joey Yap в качестве `effectiveStem` используется **фактический месячный небесный ствол**. Для августа 2026 это 丙. Использование 旬首仪 вместо месячного ствола даёт неправильный дворец, в частности Юго-восток вместо Юга.

Расчётный путь имеет вид:

```text
солнечный год + месячный Gan-Zhi → Joey Yap Month Ju
→ фактический месячный ствол → месячная карта
→ дворец Ji Fu
```

Контрольные различия:

| Режим Mingli | Август 2026 | Положение Ji Fu |
|---|---:|---|
| Guam Ham Hai | Инь 4 | Северо-запад |
| Joey Yap | Инь 7 | Юг |

Эти режимы нельзя смешивать. Значение Инь 7 не является Guam Ham Hai для августа 2026.

## Дневной уровень: Joey Yap Day Chart

Дневной уровень использует отдельный суточный цикл Joey Yap и не должен использовать часовую схему 置闰. Функция `dayJoeyYapJuForDate()` определяет Иньский или Янский Dun по текущему солнечному термину, находит ближайший 甲子-якорь около соответствующего солнцестояния и рассчитывает движение Ju по девяти дворцам.

Для контрольного ряда пользователя на 13–16 августа 2026 зафиксирована последовательность дневного Ji Fu:

| Дата | Направление Ji Fu | Дневной Ju |
|---|---|---:|
| 13.08.2026 | Запад | Инь 8 |
| 14.08.2026 | Юго-запад | Инь 7 |
| 15.08.2026 | Восток | Инь 6 |
| 16.08.2026 | Север | Инь 5 |

Дневной Joey Yap и месячный Joey Yap являются разными уровнями с разными входными данными. Совпадение названия школы не означает, что месячный Ju можно рассчитывать через дневной цикл.

## Часовой уровень: Zhi Run / 置闰

Часовая карта строится функцией `buildChart()`. Часовой Ju определяется через `juForDate()` по схеме 置闰. В расчёте используются солнечные термины, 符头, три Yuan, возможный leap-блок 芒种/大雪 и направление Dun.

После определения часового Ju карта использует часовой Gan-Zhi, 旬首仪 и положение часового ствола. Именно часовой слой определяет сектор Ji Fu для конкретной двухчасовки.

Расчётный путь имеет вид:

```text
дата + солнечный термин → Zhi Run Ju → часовой Gan-Zhi
→ 旬首仪 и часовая карта → дворец Ji Fu часа
```

Метод Chai Bu не используется как скрытый fallback. Если Zhi Run не может определить Ju, расчёт должен сообщить об ошибке, а не незаметно перейти на другую школу.

## Синтез четырёх уровней

`computeJiFuWishes()` рассчитывает четыре независимых дворца:

```text
yearPalace  = годовой Ji Fu
monthPalace = месячный Joey Yap Ji Fu
dayPalace   = дневной Joey Yap Ji Fu
hourPalace  = часовой Ji Fu по Zhi Run
```

Сила совпадения считается относительно часового дворца:

```text
strength = 1
  + совпадение года с часом
  + совпадение месяца с часом
  + совпадение дня с часом
```

В результате выводятся только случаи с силой от 2 до 4. Пользователь видит практический результат совпадения, но не обязан знать внутренние названия расчётных школ.

## Правила изменений

При изменении дневной системы нельзя менять месячную. При изменении месячного Joey Yap нельзя менять Guam Ham Hai, дневной цикл или часовой Zhi Run. Любая замена метода должна сопровождаться контрольной проверкой как минимум для августа 2026 и для переходов солнечных месяцев.

Если изменяется OpenAPI-модель Ji Fu, после этого необходимо запустить codegen. Изменения базы данных для данного расчётного слоя не требуются.
