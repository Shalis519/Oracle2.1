# Открытые источники по годовым картам Ци Мэнь

## Источники

1. Mingli QMDJ Calculator: https://www.mingli.info/qmdj
   На странице явно представлены отдельные режимы `Ju by: Hour Day Month Year`, а также отдельные системы `Day Ju: Guam Ham Hai Joey Yap` и `Month Ju: Guam Ham Hai Joey Yap`; для построения доступны `Chai Bu` и `Zhi Run`.

2. Master Feng Shui, Various Qi Men Dun Jia Chart Systems: https://www.masterfengshui.com/various-qi-men-dun-jia-chart-systems/
   Источник подтверждает, что годовая, месячная, дневная и часовая карты — отдельные подсистемы с разными функциями и правилами построения. Годовая карта используется для общей годовой энергии и годовых секторов, а месячная карта дополнительно разбивает год на 12 периодов.

3. GitHub anthonylee1994/qimen: https://github.com/anthonylee1994/qimen
   Репозиторий заявляет поддержку полной排盘-логики и имеет `ALGORITHM.md` с кодом и таблицами. Документ описывает общую часовую схему: 24节气 → 阴/阳遁 → 上中下元 → 局数 → 旬首 → 遁干 → 地盘 → 值符/值使. Его таблица局数 привязана к节气 и上中下元, то есть это не готовое доказательство годовой Mingli-последовательности.

4. GitHub ChesterRa/mingpan: https://github.com/ChesterRa/mingpan
   Репозиторий поддерживает `时盘/日盘/月盘/年盘`, а также `转盘/飞盘`, `拆补法/茅山法`, но README не раскрывает отдельную формулу годового Ju. Полезен как кандидат для дальнейшего чтения исходников.

5. GitHub dxbuyi/qimen.skill: https://github.com/dxbuyi/qimen.skill
   Python-инструмент для детерминированной时家转盘排盘. Документация делает акцент на时盘 и содержит таблицы节气/局数, но отдельного проверенного годового算法а в README не найдено.

## Промежуточный вывод

Открытые источники подтверждают, что `年盘` — отдельный уровень, но найденные GitHub-реализации преимущественно документируют时家转盘/часовые карты. Для Aether Oracle нельзя автоматически брать их сезонную формулу `节气 + 上中下元` для годового Mingli-слоя.

Наши контрольные значения от Mingli:

| Год | Mingli годовой Ju | Главные Врата | Главная звезда |
|---|---:|---|---|
| 2026 | Инь 1 | 开门 | 天心 |
| 2027 | Инь 9 | 死门 | 天芮 (с центральным 天禽/寄宫 правилом) |

Текущий годовой слой проекта после фикса 2026 использует последовательность `[1, 7, 4]` по 180-летним блокам и для 2027 даёт Инь 1, поэтому не совпадает с Mingli 2027. Требуется найти отдельное правило годового Ju, вероятно в исходниках Mingli или в китайских источниках по `年家奇门 / 年盘局数`, а не менять часовую формулу повторно.

## Дополнительные найденные правила

6. 国学典籍网, глава «年、月、日家奇门»: http://ab.newdu.com/book/ms197847.html
   Описывает годовую карту как отдельную систему: только Инь Дунь; 60 лет = один Юань/одна большая последовательность; верхний, средний и нижний Юань начинаются соответственно с Инь 1, Инь 4 и Инь 7. После выбора Юаня сначала строятся `甲子戊`, затем по годовому стволу определяется旬首/值符, а值使 привязывается к годовому земному стволу/ветви согласно изложенной школе. Для примера 2002 год указан как下元 и строится от兑七宫.

7. Chinese Text Project, 《奇门遁甲统宗》: https://ctext.org/wiki.pl?if=en&chapter=491157&remap=gb
   Классический текст подтверждает отдельную годовую схему: верхний 60-летний Юань — Инь 1, средний — Инь 4, нижний — Инь 7; полный цикл — 180 лет и используется逆. В приложении к年奇门 значение年支 используется для положения值使, а年干 — для положения值符. Это важное отличие от нашей текущей реализации, где годовой Драйвер и дворцы частично заимствовались из часового маршрута.

8. GitHub ChesterRa/mingpan, `src/services/qimen/calculators/PanTypeCalculator.ts`: локальная копия `/home/ubuntu/Oracle2.1-repo/docs/external-qimen-mingpan`
   Репозиторий заявляет поддержку年盘, но его формула `getYearPanJuShu` = `(index шестидесятилетнего года % 9) + 1`, что даёт 2026 (丙午, index 42) → 7, а 2027 (丁未, index 43) → 8. Это не совпадает с контрольными Mingli 2026 → Инь 1 и 2027 → Инь 9; использовать этот алгоритм как эталон нельзя.

9. GitHub deminzhang/qimen-go, `xuan/qimen_defs.go` и `xuan/qimen.go`: локальная копия `/home/ubuntu/Oracle2.1-repo/docs/external-qimen-go`
   `GetYearYuanJu` использует цикл HuangDiYear и 60/180-летние блоки с `_QiMenJuYear = {0,-1,-4,-7}`, то есть фактически Инь 1/4/7 по большому циклу. Для 2026 и 2027 этот репозиторий не воспроизводит Mingli-контроль 2026 → Инь 1 и 2027 → Инь 9.

10. Сводный вывод

   Открытые классические источники поддерживают 180-летнюю схему Инь 1 / Инь 4 / Инь 7, а найденные GitHub-проекты предлагают собственные упрощения. Ни один найденный открытый источник пока не объясняет контроль Mingli, где подряд 2026 = Инь 1 и 2027 = Инь 9. Значит, Mingli использует либо другую разновидность `年家奇门`, либо отдельную таблицу годовых карт/годового Ju. Нельзя подменять её классической 180-летней формулой без дополнительного первичного источника или серии контрольных карт.

## Уточняющий поиск Mingli

Поиск по `site:mingli.info 年家奇门`, `2027 奇门 阴九局` и `Mingli 年盘 奇门 局数` не выявил открытой страницы Mingli с формулой годового Цзюй или таблицей 2026–2027. Открытая страница https://www.mingli.info/qmdj показывает отдельные режимы `Ju by: Hour Day Month Year`, но сам расчёт для незарегистрированных пользователей скрыт.

Найденные общие китайские материалы продолжают описывать сезонную/180-летнюю или иную школьную схему, но не объясняют наблюдаемую пару Mingli: 2026 = Инь 1 и 2027 = Инь 9. Это подтверждает необходимость использовать контрольные карты Mingli как эталон и не объявлять найденные GitHub-формулы правильными без серии проверок.
