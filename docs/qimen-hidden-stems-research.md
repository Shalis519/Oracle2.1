# 暗干 и 隐干 в Ци Мэнь: исследовательская фиксация

Проверенные открытые материалы показывают, что термины нельзя смешивать.

## 暗干

В одном из описаний 暗干 определяется как ствол, связанный с Вратами: для конкретных Врат берётся земной ствол их исходного дворца в текущей карте. Это не обязательно тот же ствол, который непосредственно стоит в дворце, где сейчас находятся Врата.

Другие школы используют отдельную схему «飞干/隐干»: начиная с дворца 值符 раскладывают последовательность стволов по дворцам в направлении Ян/Инь. Источник прямо отмечает, что существует несколько способов расчёта 暗干.

## 隐干

隐干 описывается как «связующий» ствол: часовой ствол добавляется к дворцу Врат 值使, после чего выполняется расклад по последовательности стволов с учётом направления Ян/Инь. Он используется для определения скрытого инициатора события и не равен автоматически 暗干 Врат.

## Вывод для Aether Oracle

В текущем движке есть только `heavenStem` и `earthStem`; полей `anGan`/`yinGan` нет. Поэтому нельзя безопасно добавить `甲` рядом с `戊` только по одному скриншоту Mingli. Для точной реализации нужно зафиксировать, какой именно из вариантов использует Mingli для отображаемого скрытого ствола, затем добавить отдельное поле и тестовые эталоны. Нельзя подменять 暗干 и 隐干 одним универсальным правилом.

## TrueBazi: «Ци Мэнь: для начинающих, 2 часть»

Статья формулирует правило поиска 甲 для столпа дня или часа: 甲 считается скрытым и определяется через один из шести инструментов декады по ветви столпа. Соответствия приведены так: 甲子 → 戊, 甲戌 → 己, 甲申 → 庚, 甲午 → 辛, 甲辰 → 壬, 甲寅 → 癸. В примере автор предлагает искать соответствующий инструмент в верхнем кольце карты и использовать его как видимый ствол дня или часа.

Этот материал подтверждает, что 甲 не должен выводиться как самостоятельный обычный ствол во всех дворцах. Однако статья не описывает правило, по которому рядом с основным стволом в одном дворце одновременно рисуются малые 甲 и 乙 на обеих тарелках. Поэтому скриншот Mingli с парой малых знаков нельзя полностью вывести из этой статьи без дополнительного источника или точного описания алгоритма Mingli.

Практический вывод: правило TrueBazi полезно для определения инструмента, за которым скрывается 甲, но оно не является достаточным основанием для автоматического вывода пары 甲乙 в каждом дворце. До получения полного правила Mingli отображение пары следует считать отдельным визуальным слоем, не подменяя им расчёт небесной и земной тарелок.

Статья также содержит отдельные разделы о силе Врат, силе Звёзд, отсутствии силы у Духов, заполнении Пустоты и Наказании шести инструментов. Эти разделы относятся к интерпретации расклада, а не к базовой геометрии построения карты.

Источник TrueBazi использован как учебный открытый материал; авторство и ссылка сохранены.

## Проверка сезонной смены духов

Классический текст 《奇门遁甲统宗》 (Chinese Text Project, https://ctext.org/wiki.pl?if=en&chapter=491157) описывает расклад 八神 через полярность расклада, а не через сезонную замену: для Ян-дуня указана последовательность 值符、腾蛇、太阴、六合、勾陈、朱雀、九地、九天; для Инь-дуня — 值符、九天、九地、朱雀、勾陈、六合、太阴、腾蛇. В тексте также отмечено, что под 朱雀 располагается 玄武, а под 勾陈 — 白虎. Это не является правилом «весной один дух превращается в другой»; это альтернативные/дополнительные названия и слои духов в конкретной традиции.

Источник отдельно фиксирует сезонную связь стихий и сезонную оценку 旺相/休囚, но это не то же самое, что изменение названия Небесного духа в ячейке. В наших текущих материалах не найдено прямого правила, по которому стандартный набор 八神 автоматически заменяется по четырём сезонам.

В текущем Aether chart.ts духи строятся массивом DEITIES по шагу от дворца часового ствола и направлению Ян/Инь; отдельного season/seasonal deity слоя в построителе карты нет. Следовательно, сезонная замена духов по подходу Захарова сейчас не реализована; реализована только обычная инь/ян-раскладка 八神.
