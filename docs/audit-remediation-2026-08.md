# План закрытия аудита Aether Oracle

Дата проверки: 2026-08-19.

## Уже закрыто

- Дублирование ежедневных прогнозов ограничено уникальностью `(userId, date)`.
- Пересчёт natalChart инвалидируется при изменении даты, времени или места рождения.
- Денежная формула переведена на 84 карточки Oracle Studio из PDF «Деньги в натальной карте».
- Seed денежных карточек использует `onConflictDoNothing`, поэтому ручные правки Studio не перезаписываются.
- Seed связей онтологии использует `onConflictDoNothing`.
- API и workspace typecheck/build проходят.

## Подтверждённые незакрытые пункты

1. `GET /notepad/today` одновременно читает данные и выполняет reconciliation: создаёт, обновляет и удаляет автоматические записи. Это побочный эффект GET и затрудняет тестирование и повторные запросы.
2. `CURRENT_FORECAST_VERSION` остаётся ручным глобальным переключателем в `routes/forecast.ts`; изменение семантических данных требует правки кода и деплоя. Нужна безопасная административная инвалидация по пользователю/дате или отдельный refresh endpoint.
3. В репозитории отсутствуют регрессионные тесты для birth validation, ownership checks, daily forecast uniqueness, money formula selection и фильтрации запрещённых тел.
4. В рабочем дереве присутствует большой набор временных скриптов, docx-экспорт и незакоммиченные изменения предыдущих задач. Их нельзя удалять вслепую; нужна классификация и отдельная очистка только подтверждённых артефактов.
5. Остаётся потенциальная проблема seed-профилей: текущий `onConflictDoUpdate` меняет только пустые `plants/colors`, что уже защищает основные поля, но отдельный UPDATE исправляет историческую опечатку Jupiter при каждом запуске. Это нужно вынести в идемпотентную миграцию/одноразовый ремонт или оставить явно документированным.
6. В long-term литературном модуле сохраняется fallback-текст; требуется проверить, что в основном долгосрочном выводе он не заменяет статус `В разработке` для отсутствующей карточки.

## Приоритет исправлений

Сначала разделить notepad reconciliation и добавить защищённый endpoint; затем добавить контролируемую инвалидацию ежедневного прогноза без изменения пользовательского вывода; после этого написать тесты для ключевых правил и провести безопасную очистку временных файлов. Перед push — typecheck, build, тесты и diff-check.
