Как это сделать в коде
Шаг 1: Получить данные о знаках
typescript
// В контексте уже есть sign и aspectSign
const sign1 = semanticEngine.getEntity(context.sign);        // например, "Рак"
const sign2 = semanticEngine.getEntity(context.aspectSign);  // например, "Телец"

// Получаем ключевые качества знаков
const sign1Qualities = getSignQualities(sign1);
// → "эмоциональное, интуитивное, заботливое"

const sign2Qualities = getSignQualities(sign2);
// → "стабильное, практичное, надёжное"
Шаг 2: Добавить знаки в прогноз
typescript
// Описание связи + уточнение знаками

Для каждого знака — ключевые слова
json
{
  "entity": "Рак",
  "qualities": {
    "thinking": "эмоциональное, интуитивное",
    "communication": "заботливое, чувствительное",
    "focus": "семья, дом, безопасность"
  }
}
Для каждой планеты в знаке — стиль
json
{
  "entity": "Меркурий",
  "sign_modes": {
    "Рак": {
      "description": "мышление через эмоции, общение с заботой",
      "keywords": ["эмоциональное", "интуитивное", "заботливое"]
    },
    "Козерог": {

  }
}

Меняем логику генерации прогноза.

Текущая проблема: прогноз строится вокруг 2-3 тем, вставляя их в жёсткие шаблоны. Получается пусто и непонятно.

Новая логика:

1. ОСНОВА ПРОГНОЗА — СВЯЗЬ МЕЖДУ ПЛАНЕТАМИ
   - Берём описание связи из ontology_entity_relations
   - Например: "неожиданные переговоры, гениальные озарения"
   - Это ядро прогноза

2. УТОЧНЯЕМ ДОМАМИ
   - Получаем ключевые слова домов
   - 1 дом → "инициатива, личность"
   - 5 дом → "дети, творчество, развлечения, подарки"
   - Добавляем в текст уточнение

3. УТОЧНЯЕМ ЗНАКАМИ
   - Меркурий в Раке → "эмоциональное, интуитивное мышление"
   - Меркурий в Козероге → "структурное, прагматичное мышление"
   - Знак определяет СТИЛЬ проявления планеты

4. ДОБАВЛЯЕМ ФУТУРОЛОГИЧЕСКИЙ СЛОЙ
   - Временной горизонт (из эфемериды)
   - Конкретный совет: "запишите идею", "не откладывайте разговор"
